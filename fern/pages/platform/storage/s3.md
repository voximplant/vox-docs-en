# S3-compatible cloud storage

Voximplant allows you to export call and conference recordings directly to your own Amazon S3 or S3-compatible object storage instead of storing them in the default Voximplant cloud storage.

## How to configure S3-compatible storage

To connect custom storage, register your storage credentials in your Voximplant account and attach the storage profile to your target application:

1. Log in to the [Voximplant Control Panel]().
2. In the main navigation, go to **Settings** → **S3 storages**.
3. Click **Add storage**.
4. Enter your S3-compatible storage connection details:
   * **Host**: The endpoint URL of your storage provider (e.g., `https://s3.amazonaws.com/`).
   * **Region**: The geographical region of your bucket (e.g., `us-east-1`).
   * **Bucket name**: The exact name of your bucket.
   * **Key ID**: The access key ID with write permissions.
   * **Secret key**: The secret access key.
5. Click **Add**.
6. Navigate to **Applications**, locate your application, click the action menu (**⋮**), and select **Edit**.
7. Under **Recording storage**, select your newly created S3 storage profile from the dropdown list and click **Save**.

All future call and conference recordings initiated by this application will be saved directly into your custom storage bucket.

## Testing your storage integration

You can verify that your credentials and bucket permissions work properly before deploying live call recordings:

1. In the [Control Panel](), go to **Settings** → **S3 storages**.
2. Locate your storage profile, click the action menu (**⋮**), and select **Test**.

Voximplant uploads a small test file to your bucket and reports whether the write operation succeeded or returned an authorization error.

## Provider permissions and credentials

Your storage credentials must grant write permissions on the target bucket. Specific configuration steps vary across providers:

### Amazon Web Services (AWS)

1. Create an IAM user in the AWS Management Console.
2. Generate an Access Key (Access Key ID and Secret Access Key) for the user.

<Warning title="Save your secret key">
Store your Secret Access Key securely upon creation. AWS will not display it again after the window is closed.
</Warning>

3. Grant the `s3:PutObject` and `s3:AbortMultipartUpload` permissions on your bucket to the IAM user.
4. In the Voximplant Control Panel, configure the host URL: `https://s3.amazonaws.com/`.

Refer to AWS documentation on [S3 permissions]() and [Configuring ACLs]() for details.

### Google Cloud Storage

1. Create a service account in the [Google Cloud Console]().
2. Grant the `Storage Object Creator` role to the service account on your target bucket.
3. In Cloud Storage settings, navigate to Interoperability and generate an [HMAC key]() for the service account.
4. Save the generated access key ID and secret.

<Warning title="Save your secret key">
Store your secret key securely. Google Cloud will not display it again once you leave the creation dialog.
</Warning>

5. In the Voximplant Control Panel, configure the host URL: `https://storage.googleapis.com`.

Refer to Google Cloud documentation on [Cloud Storage IAM permissions]() and [ACLs]().

### Yandex Cloud

1. Create a service account in your Yandex Cloud folder.
2. Grant the `storage.uploader` role to the service account on the target bucket.
3. Generate a static access key for the service account and save the credentials.
4. In the Voximplant Control Panel, configure the host URL: `https://storage.yandexcloud.net`.

Refer to Yandex Cloud documentation on [Access management in Object Storage]().

### MinIO

1. In your MinIO console, create a service user.
2. Assign a policy granting `writeonly` or `readwrite` permissions to your target bucket.
3. Use the MinIO access key and secret key in the Voximplant storage configuration.

Refer to MinIO documentation on [Identity and Access Management]().

## Troubleshooting storage errors

If recording uploads fail, check your session debug logs in Call History for the following error codes:

* **`AccessDenied`**: The storage credentials do not have permission to write to the bucket. Verify that your IAM policy grants `PutObject` rights on the bucket ARN.
* **`NoSuchBucket`**: The specified bucket name does not exist or was misspelled in the storage profile.
* **`InvalidHost / ConnectionError`**: The endpoint host URL is incorrect or unreachable. Ensure the host includes the protocol prefix (e.g., `https://`).
* **`SignatureDoesNotMatch`**: The secret access key entered in the Control Panel does not match the access key ID.

## Rotating S3 access keys

When rotating credentials in your storage provider, do not delete the previous access key immediately:

<Warning title="Do not delete old keys immediately">
Updating credentials in the Voximplant Control Panel applies only to **new** uploads. Recordings or multi-part uploads already in progress will continue using the previous access key until completion. Deleting the old key immediately will cause in-flight uploads to fail with `AccessDenied`.
</Warning>

Recommended key rotation workflow:

1. Generate a new access key in your cloud provider's IAM console.
2. Update the credentials in your Voximplant S3 storage profile.
3. Run a test upload in the Control Panel to verify that new uploads succeed.
4. Keep the old key active in your cloud provider for at least **12 hours** to allow existing and queued uploads to finalize.
5. Delete the old key from your cloud provider console once all pending uploads have cleared.
